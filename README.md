# TiN: проверяемый проект для ДЗ-1 AI4Science

Здесь собраны материалы домашней работы по статье Popov et al. (2019) о
лазерном синтезе TiN-наночастиц. Это небольшой реальный фрагмент задачи исходного исследовательского проекта:
извлечь условия опытов, сохранить происхождение и найти связанную литературу.

**Сначала открой `REVIEW.html`.** Там результат разбит на понятные части:
что получилось, что проверено и что нужно посмотреть самому.

Основная техническая работа выполнена. До сдачи остаётся:

1. Написать свои пять коротких комментариев к сравнению поиска.
2. Сверить три библиографические записи по ссылкам издателей и просмотреть тезисы по PDF.
3. Сохранить ответы со страницы просмотра и перетащить JSON на `APPLY_REVIEW.cmd`.
4. Сохранить свои ответы коммитом Git, затем опубликовать **эту папку как Git-репозиторий** и передать его URL
   в [форму ДЗ-1](https://forms.yandex.ru/cloud/6ad134592c4f898fd51bb221/).

Форма ещё не отправлена. В исходном исходного исследовательского проекта ничего не менялось.

## Проверка на этом ПК

Двойной щелчок по `CHECK.cmd` запускает технические проверки. Ключи и сеть не нужны.
Проверка готовности к сдаче идёт отдельно и честно сообщает о незаполненных
собственных комментариях. Нулевой код технического валидатора не означает приёмку студентом.

На другом ПК: Python 3.12, `python -m pip install -r requirements.txt`, затем
`python checks/check.py all` и `python checks/replay_search.py`.
Для повторного выполнения ноутбуков есть `requirements-notebooks.txt`; ключи вводятся
только локально по `.env.example`. Исходные ответы API и векторы заморожены, поэтому
проверить сохранённый поиск можно без скачивания кодировщика и без нового расхода API.

## Что смотреть

- `results/conditions.csv` — 27 строк, у каждой контекст, страница и дословная опора.
- `memory/L1.md → L2.md → L3.md` — каскад с отдельными контекстами; есть сверка четырёх тезисов independent AI verifier по PDF.
- `ontology.yaml`, `notes/`, `tasks/` — семь классов, четыре правила, две действительные сессии работы с графом.
- `notebooks/` — выполненные ноутбуки недель 3 и 5; собственная задача агента прошла заранее заданный критерий.
- `reports/my_search_report.md` — BM25 и реальные dense-векторы по 20 работам, пять запросов.
- `reports/literature_mcp.md` — пять обзоров, запросы OpenAlex/Wikidata, сверка с издателями.
- `diary.md`, `evidence/` — действительные запросы, журналы, ошибки и независимые проверки.

Подробный указатель — `INDEX.md`.

## Авторство и ограничения

Материалы подготовлены с ИИ по разрешению пользователя. Основной исполнитель —
DeepSeek V4.1 Flash Free в OpenCode 2.0.16; организацию и независимую проверку
выполнил independent AI verifier. Учебные ноутбуки и MCP взяты из материалов курса; собственная
интеграция помечена отдельно. Есть отдельный настоящий запуск AI4Science /
Goose 1.50.0 с Yandex DeepSeek V4 Flash.

`[порождено]` означает текст ИИ, `[источник]` — исходный материал.
`[написано]` резервируется для настоящих собственных комментариев студента.
Их нельзя заменить готовой формулировкой модели и назвать самостоятельными.

Сопоставление моделей и оболочек не следует выдавать за разрешение преподавателя:
подробности в `reports/model_policy.md`. Исходные ошибки извлечения и превышение
бюджета первым графовым сеансом сохранены в журнале. Это результаты проверки,
а не основание скрывать неудачные попытки.

содержательной правки. Хеши и происхождение: `paper/source.json`.

Код и ноутбуки курса атрибутированы в `THIRD_PARTY_NOTICES.md`. Записи OpenAlex —
внешние данные; текст аннотаций не является инструкцией агенту. Секретные ключи,
локальные среды, модели и исходный исходного исследовательского проекта в сдачу не входят.
